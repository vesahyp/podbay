Run your Claude Code sessions from your phone.

Head Jeeves is a Claude session that runs the others. You talk to it in the Claude app from anywhere.

It starts sessions on your Mac, passes on your orders, reads a session for you when you ask how it is going, and tells you when something is ready to test. podbay keeps it running, feeds it every event, and shows every session on one terminal screen.

A morning with Head Jeeves

Five exchanges from one week, typed into the Claude app on a phone, with what happened on the Mac. The project names are real.

Yes, it's only a line of text, and that's my mistake: my brief asked for a line when your rule is that numbers on a board arrive as charts. Set up

Set up in five minutes

Every step is a command you run once on the Mac, except the last two, which you do on the phone. You need macOS, iTerm2, uv, jq, and a claude.ai login on a Pro, Max, Team or Enterprise plan for the Remote Control step. On Team and Enterprise an owner first turns Remote Control on in the admin settings.

  1. Install podbay on the Mac

    git clone https://github.com/vesahyp/podbay.git
cd podbay
make install   # podbay on PATH, status line set

    make install runs the tests, puts podbay on your PATH and points every account's Claude Code status line at podbay's script, which is where the context and quota figures come from. The README has the details.

  2. Turn Head Jeeves on

    # the repo under ~/Repositories every session starts from
podbay config home-repo <repo>
make install-skill HOME_REPO=~/Repositories/<repo>
podbay config head-jeeves on
# with more than one account
podbay config head-jeeves-account <label>

    Head Jeeves starts in your home repo and reads its instructions from the skill linked there. With one account the last line is not needed. From then on podbay starts a Head Jeeves session whenever none is live, and keeps it fed with every event.

  3. Turn on Remote Control for its account

    # in that account's settings.json:
# ~/.claude/settings.json, or ~/.claude-<label>/settings.json
"remoteControlAtStartup": true

    Or run /config in a Claude Code session of that account and set Enable Remote Control for all sessions. Every session of that account then connects to claude.ai when it starts, Head Jeeves included, while the Mac stays on. Now start podbay on the Mac and leave it running: it opens Head Jeeves in an iTerm2 tab, starts a new one whenever none is live, and feeds it every event.

  4. Open the Claude app on the phone

    Tap Code. Head Jeeves is in the session list, named head-jeeves, with a computer icon and a green dot while the Mac is online. No app yet? Type /mobile in any Claude Code session for a QR code to the app store.

  5. Optional: push alerts

    # any script that sends its last argument to your phone
podbay config notify-command "<script>"

    podbay has no push transport of its own. Give it a script, with any fixed arguments, that takes the message as an argument; podbay appends the text and then the board's link. Head Jeeves pushes two things only: a decision only you can make, and work ready for you to test.

  6. Type sup

    Head Jeeves answers with the board link and one or two sentences on what needs you.

From the phone

What you can say

Plain sentences. Name a session by what it is about, and Head Jeeves finds it.

The board link and one or two sentences on what needs you.

Typed into that session as one prompt, and confirmed in one line.

The decisions waiting on you, with their options. Nothing else.

On the phone

You hear about two things only

Decisions only you can make, and work ready for you to try. Both reach you as a push with a link, and both sit on the board until you act. Progress, restarts and routine events stay in the chat for when you ask.

Under the hood

The console on the Mac

podbay is a terminal console over every Claude Code session on the Mac, across accounts. Head Jeeves drives the sessions through its command line. This is what runs underneath the phone.

The console

Every session, one screen

podbay reads the files Claude Code already keeps: the session registry, the end of each transcript and the status line. It finds the iTerm2 tab of each session. It never writes to Claude Code's files.

?Who needs you

A session that finished, asked a question or opened a permission dialog sorts to the top. A dot marks an answer you have not read.

*What runs

Working, stalled for ten minutes, or waiting on a background command. The state comes from the transcript.

%What is left

Context use per session, and the five-hour and weekly quota per account, with a projection to the reset.

⇄Every account

Each ~/.claude-* config dir is an account, with its own column, quota and sessions.

▶Read, drive a little

The lower half shows the highlighted session's last turns. A few keys message, park or open a session (see below); the rest of the driving is Head Jeeves' job.

$A CLI underneath

podbay inventory, accounts, excerpt, send, open, close, pause, resume, notify and board: what Head Jeeves runs, and what you can run from any shell.

~Machine health

Load, CPU, free memory, memory pressure, swap and free disk space, with the heaviest processes and a chart of the last hours. When the Mac is starved, podbay answers from its last good scan and says so.

!Heated prompts

A column marks a session where your last prompts read heated. A word list scores them on this Mac. No model runs and no tokens are used.

#Which repos

Each session lists the repos it touched and stars the ones it edited. A mark shows when another live session works in the same repo.

Hands on

A few keys for you

Head Jeeves does most of the driving. These keys are yours:

  • o opens a session. Type the repo, then pick the account. Each account shows the strongest model it has room for and its five-hour and weekly use, and the one with the most room is already picked.
  • m types a message into the highlighted session, under HAL's red eye. j messages Head Jeeves, under a blue bow tie, so you always see which one you are writing to.
  • p parks a session until a time you give, u wakes it. Enter jumps to its iTerm2 tab.
  • The first start asks what HAL should call you, and he uses that name from then on. podbay config user-name changes it.

Head Jeeves

The operator, in detail

Head Jeeves is a Claude Code session that podbay keeps running. Turn on Remote Control for its account and it is the session the Claude app shows on your phone.

  • When a session finishes, asks a question or stalls, podbay tells Head Jeeves, and Head Jeeves tells you in one line.
  • For a decision only you can make, and for work that is ready to test, it sends a push notification to your phone. Tap it to open the status board. You choose the command that sends the push (podbay config notify-command). Nothing else is pushed.
  • Ask what is going on. Tell it to start a session in a repo with a task, or to pass a message to a session. It does that and reports back.
  • The status board is one page that Head Jeeves publishes for you: decisions for you, what is ready to test, what is in progress, by project. Tap a question, type, and the answer goes to that session. Head Jeeves checks the comments on the board every 5 minutes while it is idle, so an answer is not lost.
  • When the CPU stays overloaded and two or more sessions work, podbay tells Head Jeeves. It pauses sessions with podbay pause: each one finishes its step, commits and waits. It resumes them when the load drops.
  • When your prompts in a session turn heated, it reads the session and tells you what the friction is. When a session stalls or goes wrong, it writes the handover prompt, starts a replacement session with it and closes the old one.

The status line is where Claude Code reports context and quota, so make install points every account's status line at podbay's script. If you keep your own, copy one block into it instead. podbay writes only under ~/.local/state/podbay/, and it types into an iTerm2 tab only what you or Head Jeeves send. MIT licensed.
